# testfile File-Directory Pre-processing Connector

Auto-generated by EY SAM Studio. Implements the **Bridge → Source / Error**
data-quality pipeline against a directory of CSV exports.

## Pipeline

1. **CSV → Bridge** — every CSV (1 files) is read and copied
   into the `bridge` schema unchanged. A `__source_file` column is added
   to every Bridge row recording the originating CSV filename for lineage.
2. **Pre-processing filter** — `rules.sql` is executed against the Bridge.
   This single optimized query is the result of combining 0
   approved data-quality rule(s).
3. **Schema split** — rows that violate any rule land in the `error`
   schema (with `__rejected_at` / `__rule_id` / `__source_file`); rows
   that pass every rule are promoted to the `source` schema.

## Quick start

```bash

pip install -r requirements.txt

# Container

docker run --env-file .env -v $SOURCE_DIR:/data/servicenow servicenow-connector
```

## Table naming convention

Every physical table this connector creates follows the pattern
`<stage>_tbl_servicenow_<base>` (e.g.
`bridge.bridge_tbl_servicenow_cmdb_ci_server`). This is enforced at
runtime by `table_naming.assert_physical_name()`, which runs before
every `CREATE TABLE`. If you see a
`ValueError: ... does not match the <stage>_tbl_<source>_<base>
convention`, a caller is hand-rolling a name — route it through
`table_naming.physical_name(stage, source, base)` instead.

For backward compatibility, a `CREATE OR REPLACE VIEW <bare>` alias
is emitted alongside every physical table so existing SQL that refers
to the bare base name (`bridge.cmdb_ci_server`) keeps working.

## One-time legacy migration

On the first run against a database that predates this convention,
`schema_manager._migrate_legacy_bare_tables()` quarantines any
bare-named TABLE found in the bridge/source/error schemas by
renaming it to `<base>__legacy_pre_naming_convention` via
`ALTER TABLE RENAME`. **No data is lost.** The rename preserves
indexes, constraints, and row counts. You will see log lines like:

    WARNING  Renamed legacy bare table bridge.cmdb_ci_server to
             bridge.cmdb_ci_server__legacy_pre_naming_convention

This is expected and happens at most once per table. The quarantine
tables can be dropped manually once you have confirmed the new
physical tables contain the expected data:

    DROP TABLE bridge.cmdb_ci_server__legacy_pre_naming_convention;

Fresh installs (no bare tables present) skip this step silently.
